## 安装

1. 从 [Releases](https://github.com/Kkwans/telegram-archive-kit/releases) 下载 `TelegramArchiveKit_vX.X_windows_amd64.zip`；
2. 解压到任意目录，例如 `C:\Tools\TelegramArchiveKit\`；
3. 双击 `TelegramArchiveKit.exe` 运行。

程序目录和数据目录（档案库）是**分开的**：程序目录可以随时删除替换，档案库才是你的数据。

## 首次启动与登录

首次启动会引导选择**档案库位置**：

- 默认位置：`文档\Telegram Archive Library`；
- 也可以选择任意磁盘上的自定义目录，或便携模式（档案库放在程序目录内）。

然后进入「Telegram 账号与会话」菜单登录：

- **二维码登录**：用 Telegram App 扫码；
- **验证码登录**：输入手机收到的登录验证码。

会话数据由 tdl 保存在 `%USERPROFILE%\.tdl`，登录一次即可，后续下载复用会话。可用「连接测试」确认会话状态。

> 如果机器上没有 tdl，程序会自动从 tdl 官方 GitHub Release 下载安装（SHA-256 校验后安装到用户目录，不修改系统全局设置）。也可以手动下载 tdl 放入 PATH。

## 导入消息数据

TAK 的消息源是 **Telegram Desktop 导出的机器可读 JSON**（`result.json`）：

> Telegram Desktop → 打开聊天 → 右上角 ⋮ → 导出聊天记录 → 选择格式 *机器可读 JSON* → 导出。

三种导入方式：

1. **拖拽**：把 `result.json` 直接拖到 `TelegramArchiveKit.exe` 图标上；
2. **文件选择**：菜单「添加/更新聊天」→ 选择 JSON 文件（可多选）；
3. **粘贴路径**：在菜单中粘贴 `result.json` 的完整路径。

同一聊天可以多次导入：TAK 按 **Chat ID** 识别聊天、按 **Message ID** 增量合并新旧消息，不会产生重复。每次导入的原始 JSON 都会快照保存到 `chats/<聊天>/source/history/`，可随时回溯。

## 一键完成

「一键完成」是把一个聊天从导入到可浏览的全部步骤串起来：

```text
导入 JSON → 环境预检 → 智能补齐媒体 → 构建 Viewer → 完整性校验 → 打开网页
```

- **环境预检**：检查美化主题、FFmpeg、媒体一致性、tdl 可用性、磁盘空间预估；
- **智能补齐媒体**：按 Message ID + 实际文件大小计算真正缺失的媒体，生成下载计划并执行（详见[下载设置详解](#下载设置详解)）；
- **构建 Viewer**：扫描 → 缩略图 → 完整性 → 数据序列化 → 搜索索引 → 日期索引 → HTML 分页 → 报告。

任何一步失败都会进入恢复菜单，可以重试、重新登录、查看 tdl 日志或先生成部分网页。日志保存在 `Library/.logs/`。

也可以在「同步全部聊天」中对库内所有聊天逐个执行预检 → 补齐 → 构建。

## 继承官方 ChatExport

如果你以前用 Telegram Desktop 导出过 HTML 版聊天记录（包含 `messages.html`、`messages2.html`、`photos/`、`video_files/`、`files/` 等），可以直接把这份历史导出**继承**进 TAK，复用其中的媒体文件，只下载缺失部分。

支持的典型结构：

```text
小美_2026-03-20/
├── photos/
├── video_files/
├── files/
├── messages.html
└── messages2.html
```

目录名可以随意改，不影响识别；CSS/JS 是否被替换过也无妨。入口：菜单「继承 Telegram 官方 ChatExport」。

### 三种导入模式

| 模式 | 行为 | 适用场景 |
|---|---|---|
| **纳管** | 把整个目录纳入档案库。同盘通常直接重命名（瞬间完成）；跨盘则先完整复制、确认无误后才删除源目录 | 希望档案库自包含 |
| **引用原目录** | 不复制任何媒体，立即完成，档案库记录原目录路径 | 历史导出几十上百 GB、已在另一块盘上。**注意：原目录之后不能移动或改名** |
| **复制** | 保留源目录，再复制一份进档案库 | 最安全，代价是双倍磁盘占用 |

跨盘复制使用 `.tak-part` 临时文件：复制完整后才改成最终文件名，同名同大小的文件自动跳过，因此**中途取消或断电都不会损坏已有数据**，下次可以继续。传输期间 Windows 会启用后台低 I/O 优先级，不拖累前台使用。

### 推荐流程

1. 「继承 Telegram 官方 ChatExport」→ 选择旧导出目录 → 选择纳管 / 引用 / 复制；
2. 再导入该聊天当前的全量 `result.json`；
3. 「一键完成」。

TAK 会扫描 `messages*.html` 提取每条消息的本地媒体链接，按 Message ID 与已下载媒体比对，旧媒体直接复用，缺什么补什么。

## 聊天管理

「聊天管理」针对当前选中的聊天提供独立操作：

- **设为当前聊天**；
- **一键同步**：预检 → 补齐媒体 → 重新构建网页；
- **继承官方 ChatExport**；
- **只重新生成网页**：不联网、不下媒体，仅用现有数据重建 HTML/索引。**升级版本后执行这一项即可**；
- **导入已有 tdl 媒体目录**：把此前用 tdl 或其他方式下载过的媒体增量复制进档案库；
- **复制/抽取到另一档案库**：把当前聊天完整复制到另一个库（源聊天保留，不会被删除）；
- **打开数据目录** / **删除本地归档**（删除需在危险确认页二次确认）。

## 档案库与多磁盘

一个档案库 = 一个自包含、可整体备份/移动的完整单元。`index.html` 是唯一入口，`chats/` 下每个聊天一个独立目录，媒体互不冲突。

可以把不同聊天放在不同磁盘的多个库里：

```text
D:\Telegram Archive A
E:\Telegram Archive B
```

「档案库与存储」菜单支持：

- 切换 / 新建档案库，查看最近使用的库（8 条）；
- **合并**：把库 B 合并进库 A（先按 Chat ID 合并 JSON，再增量复制媒体；源库只读不删除）；
- **抽取/复制**：把某个聊天从 A 复制到 B；
- **整库迁移**：把当前档案库复制到新位置（低 I/O 优先级、可断点续传）。

> 设计取舍：TAK 有意**不让一个聊天的 `media/` 跨两个盘**。跨盘软链接和绝对路径会让浏览器兼容性与可迁移性变差，因此采用"多个独立库 + 显式合并/抽取"的方案。

## 下载设置详解

在「设置与诊断 → 下载设置」中可调整：

| 设置项 | 默认值 | 说明 |
|---|---|---|
| 并发文件任务 | 2（1–8） | 同时下载的文件数 |
| 单文件线程 | 4（1–16) | 每个文件的分片线程数 |
| 无进展暂缓阈值 | 60s（30–600s） | 超过该时间无任何字节进展，暂缓该文件、重建队列先下载其他文件 |
| 网络恢复窗口 | — | 网络错误后按 2/3/5/8/13/20/30 秒指数退避重试 |
| 疑难文件重试次数 | 3（1–10） | 对反复失败的文件单独重试的轮次预算 |
| 重试传输策略 | increase | 疑难文件重试时调整并发/线程：增大线程（默认）/ 同时增大（试验）/ 减小 / 保持 |
| 代理 | 关闭 | 为 tdl 配置代理 |

下载可靠性机制：

1. **健康文件优先**：正常文件按计划下载，不会被坏文件阻塞；
2. **无进展看门狗**：针对 tdl 在 Windows 上可能长时间卡在 0 B/s 的问题（[iyear/tdl#1071](https://github.com/iyear/tdl/issues/1071)），自动暂缓问题文件并继续其他任务；
3. **诊断性重启**：重试预算耗尽后，允许对整个下载引擎做一次诊断性重启（预算跨所有补漏轮次共享），然后对疑难文件再给一轮预算；
4. **失败收尾**：全部预算用完后结束并列出失败媒体 ID，不做无限重试；完成后以实际文件为准核对完整性。

同步界面实时显示：总进度（已归档/总数、总字节、速度、ETA）、正在下载的媒体列表、本次运行最近完成的媒体及耗时。

## 缩略图与 FFmpeg

- 构建网页时默认为每张本地图片生成约 720px 的 JPG 缩略图，缓存在 `chats/<聊天>/thumbs/`，后续构建只补新图，可在设置中关闭；
- 图片缩放由 Go 标准库完成；**视频海报帧、HEIC/WebP 解码**需要 FFmpeg；
- FFmpeg 缺失时，开启缩略图功能的环境预检和网页重建会**自动下载安装**（来源 gyan.dev，SHA-256 校验，安装到 `%LOCALAPPDATA%\Programs\TelegramArchiveKit\ffmpeg\`，过程显示进度且支持 Esc 取消）；
- 无法解码的媒体仍会正常列出（显示文件名与下载链接），缺失封面的数量记录在 `archive-report.json` 的 `missing_image_previews` / `missing_video_previews` 中。媒体本体永远不会因此丢失。

## 浏览档案库网页

双击档案库 `index.html`（或从菜单打开）进入 **Prism Archive**：

- **首页**：所有聊天的卡片视图，支持按更新时间 / 创建时间 / 最新消息 / 消息数 / 媒体数排序（升降序，选择被记忆），侧栏列出全部聊天与统计；
- **聊天页**：消息分页浏览（每页 1000 条），支持回复、转发、表情回应、spoiler、代码块等 Telegram 消息元素；
- **搜索**：`/` 或 `Ctrl+K` 唤起，跨所有分页全文搜索，支持媒体预览、键盘上下选择；
- **日期导航**：日历按钮跨页跳转到任意日期，定位时日期行与消息双脉冲高亮；
- **灯箱**：点击图片/视频进入全页灯箱，支持缩放、平移、键盘翻页、图片/视频筛选、打开原文件；
- **六种合并模式**（顶栏下拉切换）：

| 模式 | 合并策略 |
|---|---|
| 智能合并（默认） | 同发送者相邻 15 分钟内的安全消息聚合为卡片（确定性规则，非 AI） |
| 原版（严格） | 只保留导出数据中带真实 `grouped_id` 的相册，其余逐条显示，零推断 |
| 原版（还原） | 真实相册优先；对无标题的连续 document 文件做保守推断 |
| 同分钟合并 | 同发送者同一自然分钟内的相邻消息 |
| 同发送者合并 | 同发送者相邻 1 小时内的消息 |
| 媒体批次合并 | 同发送者相邻 3 分钟内的安全媒体消息 |

> 六种模式均不修改原始数据；切换模式通过 URL `?mode=` 参数记忆。「媒体尚未同步」标记表示该消息的媒体还没下载完成，重新同步后会消失。

网页是完全离线的静态文件，可以复制到 U 盘、NAS 或任何地方直接打开。

## CLI 子命令

```text
TelegramArchiveKit.exe version          # 查看版本
TelegramArchiveKit.exe selftest         # 离线自检
TelegramArchiveKit.exe build <result.json> <media-dir> <out-dir>   # 从现有数据生成独立网页
TelegramArchiveKit.exe verify           # 校验档案库完整性并输出统计
```

## 升级版本

1. 保留旧版本目录与档案库；
2. 把新版本解压到**新目录**；
3. 启动新 EXE，确认档案库指向原位置；
4. 执行「聊天管理 → 当前聊天 → 只重新生成网页」（或「同步全部聊天」）。

无需重新登录、重新导入或重新下载任何媒体。**任何时候都不要删除档案库目录。**
