# 远程 / NAS 档案库调研（3.0 方案）

你的 NAS（例如绿联 192.168.5.110）完全可行，建议分两步做，避免在 2.0 里引入不成熟的网络协议实现。

## 结论

- **推荐第一步：直接使用 Windows 已挂载的网络位置或 UNC 路径**，例如 `Z:\TG Library` 或 `\192.168.5.110\share\TG Library`。
- 现有的导入、下载、构建、媒体读取、HTML 生成都基于普通文件路径，理论上不需要改业务代码；难点集中在写入锁、磁盘空间检测、缩略图/网页的首屏延迟和 NAS 掉线处理。
- **不建议在 3.0 之前自研 SMB 客户端**。Windows 已有凭据管理、SMB 多通道、缓存与断线恢复；直接复用映射盘/UNC 比带账号密码的纯 Go SMB 客户端更稳。

## 可行性拆解

### 1. 路径与文件操作
- `os`、Go 的 `filepath`、ffmpeg、tdl 都可以处理映射盘和 UNC 路径。
- 文件选择器需要允许输入/选择 UNC；目前原生目录选择器可以直接选择映射盘，也可手动输入网络路径。
- NAS 上必须测试：中文路径、空格、`#`、长路径、文件名大小写、符号链接/回收站。
- 需要在选择时做一次写入测试（创建临时文件后删除），否则用户可能选到只读共享。

### 2. 并发与锁
- 当前桌面端用会话锁文件保护档案库。SMB/NFS 的文件锁语义与本地 NTFS 不完全一致。
- 3.0 建议：本地仍保留“本机互斥锁”，NAS 上使用带实例 ID 和心跳的锁文件，并给用户明确的“另一个设备正在写入”提示；不要依赖单机 `syscall` 锁。
- tdl 临时文件、网页构建的原子 rename、导入时的移动都要在 SMB 上验证；必要时在 NAS 模式下降级为“先写本地临时目录，再整体复制/重命名”。

### 3. 磁盘空间
- 现有 `GetDiskFreeSpaceExW` 对 UNC 路径通常可用，但部分 NAS/网关返回 0 或不支持。
- 需要增加 fallback：显示“未知”，而不是误报 0；下载前若无法读取空间，给出警告而不是直接拒绝。
- NAS 配额、回收站和快照会改变实际可用空间，界面应标注“NAS 报告值”。

### 4. 媒体与网页首屏
- 直接通过 HTTP `http.ServeContent` 从 SMB 读文件是可行的，Range 也支持，但 NAS 的随机读延迟会放大视频首帧和缩略图加载时间。
- 现有本地视频 faststart 缓存可以直接复用：在**本机**生成 faststart 播放副本，避免每次从 NAS 全量读取 moov 后再播放。
- 建议 3.0 增加**本机派生缓存**：
  - 缩略图、视频 faststart 副本、网页构建中间文件缓存到 `%AppData%\TelegramArchiveKit\remote-cache\<library-id>`；
  - 以源文件 mtime + size 作为缓存键；
  - 设置缓存上限（例如 8 GB）和“清理远程缓存”按钮。
- HTML 网页资源仍建议写回 NAS，便于其他设备直接浏览；如果用户希望只读，则提供“本地预览缓存”模式。

### 5. 离线与错误处理
- NAS 断线时，所有文件操作可能阻塞数十秒。需要统一的超时上下文和“NAS 不可达”状态页。
- 历史统计、聊天列表等只读信息可以缓存到本地；下载、构建、删除等写操作在 NAS 不可达时禁用。
- 切换档案库时检测网络路径，提示“远程库”；顶部标题栏和诊断页显示连接状态。

### 6. 凭据与安全
- 首选使用 Windows 凭据管理器/已映射驱动器；应用不保存 SMB 密码。
- 3.0 可增加“网络位置”面板：输入 UNC、测试连接、提示通过 `net use` 或 Windows 凭据管理器挂载。
- 不建议在配置文件中明文保存 NAS 密码；后续如支持 SMB 客户端，使用 Windows DPAPI 加密凭据。

## 实施建议（3.0）

1. **远程路径识别与选择**
   - 接受 `\server\share` / 映射盘；
   - `IsRemotePath` 检测；
   - 选择时执行写入/读取/空间测试。
2. **远程库状态**
   - 顶部标签“远程库”；
   - 诊断页增加 NAS 可达性、延迟、可用空间、缓存占用；
   - 断线禁用写操作。
3. **缓存**
   - 本地缩略图缓存（按源 mtime）;
   - 本地 faststart 播放缓存（现有逻辑扩展到远程）；
   - 下载/构建临时文件本地化。
4. **并发**
   - 远端锁文件 + 心跳；
   - 多设备写入冲突提示。
5. **测试**
   - 192.168.5.110 的真实共享；
   - 千兆/ Wi-Fi、断网恢复、只读共享、中文/空格路径、长时间播放。

## 与在线 tdl 能力的关系

- 远程档案库与 tdl 在线导出是两件独立的事：前者解决“库放在哪”，后者解决“聊天列表与导出不用手动”。
- 两者可以一起放在 3.0：在线导出得到的 result.json/媒体直接写入 NAS 库；下载/构建任务在本地缓存后回写 NAS。
- 2.0 保持本地路径 + 自动 faststart 缓存，不改变用户已有 TG Library。

## 2026-11-06：3.0 实施结果与 3.1 评估

3.0 已落地的远程库路线以“把远程变成可用的文件路径”为核心，避免在现有导入、下载、构建、媒体读取链路上引入 VFS 重构：

- **SMB / UNC、映射网络盘**：应用内“网络位置”向导，检测远程路径，执行读、写、延迟与可用空间测试；状态卡、离线横幅与诊断行已接入。
- **rclone + WinFsp**：检测已安装工具和已配置 remote；可在应用内把 remote 挂载为盘符并做写入测试，退出 TAK 时结束自己启动的挂载进程。已用真实 rclone + 本地 remote 实测挂载/卸载。
- **SSHFS-Win**：提供安装命令和 `\sshfs\user@host` 映射引导；不保存 SSH 密码。
- **远程缓存**：缩略图按源文件 mtime + size 缓存在本机 `remote-cache/<library-id>`；视频 faststart 继续复用现有本地播放缓存；弹窗提供缓存占用与清理入口。

### 原生 SFTP / Remote Agent（3.1 评估）

- **原生 SFTP 镜像**：不挂载时需要一个本地镜像/VFS 层，所有写操作要处理冲突、断点与回写，风险高于收益；3.0 不采用直接 SFTP 写库。
- **NAS Remote Agent**：在 NAS 上运行一个小型 HTTP 服务（Docker/二进制），桌面端只做协议和缓存；最适合多设备、无挂载、无驱动场景，但需要部署与版本兼容维护，列为 3.1 首选评估方向。
- **结论**：3.0 以 SMB/UNC + rclone/SSHFS 挂载覆盖绝大多数用户；3.1 优先验证 Remote Agent，而不是仓促实现纯 SFTP 写库。

## 4.0 桌面端的 SSH / SFTP 接入

在「档案管理 → 网络位置 → SSH 连接」选择已有的 OpenSSH 主机，输入 NAS 上包含 `library.json` 的档案库目录，然后点击「连接并使用」。可在这里安装所需的 rclone 和 WinFsp。应用验证主机和档案库、自动分配盘符，再切换到该库。认证使用 Windows OpenSSH 已信任的主机和密钥或 SSH Agent。目录留空时使用 SFTP 登录目录。

SSH 挂载随桌面客户端运行。使用该档案库发布网页时，当前版本的服务和浏览器访问地址仍在 Windows。需要 Windows 关机后网页继续访问时，要另行将网页服务部署到 NAS 本机。
