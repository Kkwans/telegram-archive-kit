# TAK 3.0 调研：tdl 在线聊天与一键导出

> 本文只记录调研结论与方案，2.0 不实现。tdl 版本以当前随程序安装的 `0.20.4` 为准。

## 结论

**可以实现**。tdl 已经提供在线聊天列表与按聊天导出消息的能力，TAK 不必再强依赖用户手动从 Telegram Desktop 导出 `result.json`：

- `tdl chat ls -o json`：列出当前账号可见的聊天（支持表达式过滤）。
- `tdl chat export -c <chat> -o <file> --with-content --all`：按聊天在线导出消息（支持按时间、消息 ID、最近 N 条）。
- `tdl download -f <export.json> -d <dir>`：tdl 自己就能下载该导出中引用的媒体。

TAK 需要补的是一个 **tdl 导出格式 → TAK 归档** 的适配层，以及在线列表/增量更新 UI。

## 建议交互

1. 新页面「在线聊天」：
   - 进入时执行 `tdl chat ls -o json`，显示名称、类型、ID、最后消息；支持搜索与只显示有头像的私聊/群/频道。
   - 每行提供「导出到档案库」；已归档的聊天显示「更新（N 条新消息）」。
2. 导出流程（可取消、可续）：
   - 检查 tdl 登录（未登录 → 引导到账号页）。
   - 首次：`chat export -c <id> -o .runtime/online-<id>.json --with-content --all`。
   - 下载媒体：`tdl download -f <export.json> -d <workspace>/media`（沿用现有并发/线程/代理/重试设置）。
   - 适配 + 合并到 `source/result.json`，再走现有构建流水线，生成同一套离线网页。
3. 增量更新：
   - 记录已归档的最大消息 ID；用 `chat export -T id -i <lastID>,0 --with-content` 只取新增消息（需用真实账号确认 `id` 边界的包含关系）。
   - 合并按消息 ID 去重；编辑/删除消息以在线导出为准，保留历史快照到 `source/history/`。
4. 对受保护聊天/话题：`--topic` 与 `--reply` 已由 tdl 支持，可作为高级选项。

## 适配层要点

- 先用真实账号导出一个小聊天，固化 tdl JSON 的 schema（消息 ID/时间/发送者/media 字段与文件命名规则）。
- 将 tdl 消息映射为 TAK 的 `model.Message`：文本、实体、回复、转发、相册、文件、语音、贴纸、service message、话题。
- 媒体路径用 tdl 下载后的实际文件名，写入 `media/` 或 `files/`；复用现有 `archive.BuildArchiveWithDirs` 的扫描兜底。
- 无法表达的字段降级为纯文本，禁止丢消息。
- 导出文件属于临时数据，放 `.runtime/`，成功后保留最近一次以便排障。

## 风险与工作量

| 项 | 风险 | 处理 |
|---|---|---|
| tdl 导出 schema 变化 | 升级 tdl 后字段漂移 | 适配层版本化；导入前校验必填字段 |
| 大聊天 | 单次导出/下载耗时、内存占用 | 按时间段分批导出；流式解析；沿用可取消 ctx |
| 受保护/话题聊天 | API 限制或需要额外参数 | `--topic`/`--reply` 高级选项；错误透传 |
| 增量边界 | `-T id` 包含关系需实测 | 以消息 ID 对账，重复消息幂等合并 |
| 登录状态 | tdl 会话失效 | 导出前检查；失败引导重新登录 |
| 与手动导入共存 | 两种来源的同一聊天 | 以 Chat ID 识别；在线导出优先，历史快照保留 |

预估：在线列表 + 首次导出/适配/下载/构建 **5–8 人日**；增量更新 + 对账 + 边界处理 **额外 2–3 人日**；建议作为 3.0 的核心功能，而不是塞进 2.0。

## 2.0 已打好的基础

- tdl 登录、会话检查、可取消子进程与隐藏窗口。
- 下载进度内核（速度/ETA/逐项表）可直接复用。
- 档案库互斥体与原子配置写入。
- 媒体扫描、缩略图、构建、账号与诊断页面。
